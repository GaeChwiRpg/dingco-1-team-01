# 측정 2 — 틀린 건이 조용히 넘어가지 않고 검토 목록에 쌓이는가

> **측정 조건** — 이 줄이 없으면 아래 숫자는 어느 조건의 것인지 알 수 없다
>
> | 항목 | 재사용 **끔** | 재사용 **켬** |
> | --- | --- | --- |
> | 실행 시각 | 2026-08-12T13:37:51Z | 2026-08-12T14:32:39Z |
> | `classification.reuse.enabled` | `false` | `true` |
> | 모델 | `claude-sonnet-5` | `claude-sonnet-5` |
> | 자동 확정 기준값 | `0.8` | `0.8` |
> | 감사 비율(설정) | `0.05` | `0.05` |
> | 입력 | 정답 문의 50건 | **같은 50건** |
> | 커밋 | `38b2f25` | `ecbfcf5` |
>
> **새로 잰 것이 아니다.** ①③④ 는 측정 1·8ⓐ·8ⓑ 를 돌릴 때 저장한 **원자료를 다시 집계**한
> 값이고, ②⑤ 는 테스트를 돌려 얻었다. **AI 를 다시 부르지 않았다.**
> 원자료 경로: `evidence/measurement-1-8a/raw` · `evidence/measurement-8b/raw`

## 한 줄로

**틀린 건은 조용히 넘어가지 않았다.** 재사용을 끄고 돌린 50건 중 **23건(0.460)이 사람에게
갔고**, 세는 방법 두 가지가 서로 맞았다. 이상한 값은 **기준값을 넘겨도 자동 확정되지 않는다.**

---

## 1. 검토 목록에 들어온 비율과 사유별 몫

### 재사용 끔 — 50건 중 23건(0.460)이 사람에게

| 판정 | 건수 | 몫 | | 큐 삽입 사유 | 건수 | 전체 대비 |
| --- | ---: | ---: | --- | --- | ---: | ---: |
| `AUTO_ACCEPTED` | 32 | 0.640 | → | `AUDIT_SAMPLE` (일부) | **5** | 0.100 |
| `NEEDS_REVIEW` | 15 | 0.300 | → | `LOW_CONFIDENCE` (전건) | **15** | 0.300 |
| `FAILED` | 3 | 0.060 | → | `CLASSIFY_FAILED` (전건) | **3** | 0.060 |
| `REUSED` | 0 | — | | **합계** | **23** | **0.460** |

**격리는 전건, 감사는 일부다.** 확신 못 한 15건과 못 읽은 3건은 **하나도 빠짐없이** 갔고,
자동 확정된 32건 중에서는 5건만 뽑혔다.

### 재사용 켬 — 사람에게 가는 양이 0.360 으로 준다

| 판정 | 건수 | | 큐 삽입 사유 | 건수 |
| --- | ---: | --- | --- | ---: |
| `REUSED` | 32 | → | `AUDIT_SAMPLE` | **3** |
| `NEEDS_REVIEW` | 15 | → | `LOW_CONFIDENCE` | **15** |
| `AUTO_ACCEPTED` | 3 | | `CLASSIFY_FAILED` | **0** |
| `FAILED` | 0 | | **합계** | **18** (0.360) |

> 재사용 켬에서 `REUSED` 32건은 AI 호출 없이 과거 확정 답을 재사용한 건이라
> `AUTO_ACCEPTED`(3건)와 별개로 센다.

**줄어든 것은 감사 표본과 못 읽은 건이지 격리가 아니다.**

| | 왜 |
| --- | --- |
| `LOW_CONFIDENCE` **15건 그대로** | 재사용은 **확정된 답만** 담으므로(계약 C) 저확신 건을 안 건드린다 |
| `CLASSIFY_FAILED` 3 → **0** | AI 를 47번이 아니라 18번만 불렀다 — **실패할 기회 자체가 줄었다** |
| `AUDIT_SAMPLE` 5 → **3** | 모집단이 자동확정 32 → 자동확정 3 + 재사용 32 = 35 로 바뀌었다 |

> ⚠️ **「재사용을 켜면 사람 일이 준다」로 읽지 않는다.** 이번에 준 것은 **못 읽은 건**이고,
> 그건 AI 호출 횟수에 딸린 것이지 재사용이 사람 노동을 줄인 증거가 아니다. 사람 노동이 실제로
> 주는 자리는 **같은 키의 사람 답을 재사용할 때**이고, 그건 측정 11 의 몫이다.

---

## 2. 세는 방법 두 가지가 서로 맞나 — 검산

**하나로만 세면 틀렸을 때 틀린 줄 모른다.** 판정에서 역산한 값과 API 가 실제로 돌려준 값을
맞대봤다.

| 검산 | 재사용 끔 | 재사용 켬 |
| --- | --- | --- |
| **①** 판정에서 센 삽입 수 vs 큐 목록 − 측정 전 적체 | 23 vs 23 − 0 = 23 ✅ | 18 vs 36 − 18 = 18 ✅ |
| **②** 통계 API 의 적체 증가분 vs 판정에서 센 격리 | 15·3 vs 15·3 ✅ | 15·0 vs 15·0 ✅ |

### ⚠️ 처음에는 둘 다 어긋났다 — 원인은 결함이 아니라 누적이었다

첫 집계에서 재사용 켠 쪽이 이렇게 나왔다.

```text
[검산 ①] 판정에서 센 18건 vs 큐 목록 36건 → ❌ 어긋남
[검산 ②] 적체 33건, 격리 15건이 남아 있어야 한다 → ❌ 어긋남
```

**파보니 8ⓑ 는 8ⓐ 가 남긴 데이터가 DB 에 있는 상태에서 돌린 실행**이었다. 큐 목록 36건은
`이번 18건 + 지난 회차의 남은 격리 18건` 이었다.

**측정 8ⓐ 의 감사율에서 겪은 것과 같은 함정이다** — *"누적으로만 보면 틀린다. 측정 전후의
차를 내야 이번 회차의 값이 된다."* 그때 감사율에만 적용했던 규칙을 **큐 집계에도 적용**해
고쳤고, 고친 뒤 두 조건 모두 맞았다.

> 장치가 멀쩡한데 고장 신호를 내는 것이 진짜 어긋남보다 위험하다 — 다음에 진짜로 어긋났을 때
> "또 누적 때문이겠지" 하고 넘기게 된다.

### 감사 표본이 적체에서 0 으로 보이는 것은 정상이다

`stats-after` 는 **감사 확정(⑤단계) 뒤에** 찍는다. 확정된 감사 표본은 `RESOLVED` 라
적체(`PENDING`)에서 빠진다. **이걸 모르고 보면 「감사가 큐에 안 들어갔다」로 잘못 읽는다.**

## 3. 같은 문의에 신호가 두 번 와도 큐는 1건인가 (D-049)

`ClassificationServiceTest$DuplicateExecution` — **3건 전부 통과**
(`tests="3" failures="0" errors="0"`)

| 확인한 것 |
| --- |
| 두 번 불러도 **큐는 1건, 결과 행도 1건**이다 |
| 자동 확정 뒤에 다시 와도 `CLASSIFIED` 를 덮어쓰지 않는다 |
| `UNCLASSIFIED → CLASSIFIED` 는 이 경로로 못 일으킨다 — **사람만 할 수 있다** (불변 규칙 2) |

**이게 뚫리면 상담원이 같은 문의를 두 번 보고, 감사한 건수가 부풀어 오분류율이 실제보다 낮게
나온다.** 조건부 UPDATE 한 문장이 그걸 막는다.

> ⚠️ **테스트로 고정한 것이지 운영에서 신호가 두 번 오는 빈도를 잰 것이 아니다.**
> 이번 50건 실행에서 `classification_skipped` 로그는 나오지 않았다 — 즉 **이번에는 중복 신호가
> 실제로 오지 않았다.** 「막았다」가 아니라 「막을 준비가 돼 있고, 이번엔 쓸 일이 없었다」다.

## 4. 못 읽은 건이 `0` 이 아니라 `null` 로 남았나 (D-022)

| seed | `category` | `confidence` | `attempt_count` |
| ---: | --- | --- | ---: |
| 16 | `null` | `null` | 3 |
| 24 | `null` | `null` | 3 |
| 28 | `null` | `null` | 3 |

**3건 전부 두 필드가 `null` 이다.**

`confidence` 에 `0` 을 쓰면 최하위 구간에 **「AI 가 0 이라 신고한 건」과 「응답이 깨진 건」이
섞여** 측정 8ⓐ 가 오염된다. 파싱 실패는 **판정 방향 지시이지 저장 값이 아니다.**

---

## 5. 재시도가 실제로 회수하고 있나

| `attempt_count` | 건수 |
| ---: | ---: |
| 1 | 43 |
| 2 | 2 |
| 3 | 5 |

**2회 이상 시도하고도 판정이 난 건 = 4건.** (`attempt=2` 2건 + `attempt=3` 5건 중 실패 3건 제외)

**실제 AI 호출에서 재시도가 건을 회수한 증거다.** 측정 4 는 오류를 **주입해서** 재시도가 도는
것을 봤고, 여기서는 **주입 없이 실제로 회수된 4건**이 나왔다.

> ⚠️ 재사용을 켠 실행에서는 전부 `attempt=1` 이라 회수가 0 건이다. **「회수가 안 된다」가
> 아니라 「AI 를 18번만 불러서 재시도할 일이 적었다」**이다 — 이 숫자만으로는 구분되지 않는다.

## 6. ★ 값 검증 4종이 기준값 비교보다 앞인가 (D-034)

**단위 테스트로는 이미 고정돼 있었지만(TRI-49), 그것은 「파서가 무엇을 돌려주나」를 볼 뿐이다.**
**그 결과가 기준값 비교보다 먼저 쓰이는지**는 두 클래스를 이어 붙여야 보인다. 접수부터 큐
삽입까지 실제 경로로 태웠다 — `ValueCheckOrderIT`, **5건 전부 통과.**

### 순서가 뒤집히면 무슨 일이 나나

```text
확신도 1.5 를 받았다고 하자

검증이 뒤에 있으면   1.5 >= 0.8  →  자동 확정 통과
                     그 뒤에 검증에서 걸림  →  이미 확정된 뒤다
                     1.5 는 0.0~0.5 · 0.5~0.8 · 0.8~1.0 어디에도 안 들어간다
                     → 자동 확정되면서 동시에 신뢰도 구간 집계에서 사라진다
```

**측정 8ⓐ 의 분모가 조용히 줄어든다.** 감사 삽입을 트랜잭션 밖으로 빼면 표본이 조용히
새는 것(TRI-86)과 **같은 계열의 위험**이다.

### 실측

| 넣은 값 | 왜 위험한가 | 결과 |
| --- | --- | --- |
| `confidence: 1.5` | **기준값을 넘긴다** — 검증이 뒤였다면 자동 확정된다 | `FAILED` · 두 필드 `null` · `CLASSIFY_FAILED` ✅ |
| `confidence: -0.3` | 비교에서는 그냥 「미만」이라 **`NEEDS_REVIEW` 로 샐 수 있다** | `FAILED` · 두 필드 `null` ✅ |
| `category: REFUND_XYZ` | 10종에 없다. 확신도 `0.99` 로 높게 왔다 | `FAILED` · 두 필드 `null` ✅ |
| `confidence` 칸 없음 | 비교할 값이 없다 | `FAILED` · 두 필드 `null` ✅ |
| **`confidence: 0.93`** (대조군) | — | **`AUTO_ACCEPTED`** · 두 필드 채워짐 ✅ |

**대조군이 이 테스트의 핵심이다.** 넷 다 `FAILED` 인 테스트는 **비동기 배선이 끊겨 있어도
통과한다** — 멀쩡한 값이 같은 경로로 자동 확정되는 것을 함께 봐야 「검증이 앞이라 막혔다」와
「경로 자체가 안 돈다」가 갈린다.

### 범위 안으로 잘라 넣지 않는다

`1.5 → 1.0` 으로 clamp 하면 최상위 구간에 **「AI 가 1.0 이라 신고한 건」과 「1.5 를 잘라낸 건」이
섞인다.** D-022 가 `confidence 0` 을 거부한 것과 같은 논리라, **두 필드가 모두 `null`** 인
것까지 확인했다.

## 7. 이 결과의 한계

| 한계 | 내용 |
| --- | --- |
| **표본** | 50건 1회 실행이다. 사유별 비율은 **입력 50건의 성격**에 딸린 값이라 다른 문의 묶음에서는 달라진다 |
| **중복 신호는 빈도를 안 쟀다** | 테스트로 막히는 것을 고정했을 뿐, **운영에서 신호가 두 번 오는 빈도**는 모른다. 이번 실행에서는 한 번도 안 왔다 |
| **재시도 회수 4건도 빈도가 아니다** | 이번 회차에 우연히 일시적 실패가 4번 있었다는 뜻이다. 재시도의 **성공률**로 읽으면 안 된다 |
| **⑤ 는 목으로 주입했다** | 실제 AI 가 `1.5` 를 낼 확률은 안 쟀다. 확인한 것은 **「오면 막힌다」**이지 「자주 온다」가 아니다 |
| **두 조건은 다른 실행이다** | 재사용 끔/켬 비교는 같은 입력이지만 **다른 회차**라, 차이를 그대로 「재사용의 효과」라고 부르지 않는다 |
| **모델 한정** | `claude-sonnet-5` 에 한정된다 (D-024) |
