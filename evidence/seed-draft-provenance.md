# 정답 문의 50건 — 문장을 누가 썼나

> D-046 ⓑ 가 요구하는 기록이다. **AI 로 초안을 만들었으면 그 사실을 적는다** — 안 적으면 나중에 "왜 이렇게 잘 나왔나"에 답할 수 없다.
> 대상 파일: `src/test/resources/seed/inquiries-50.csv`

## 왜 이 기록이 필요한가

같은 계열 모델이 만든 문장은 **그 모델이 분류하기 쉬운 쪽으로 치우친다.** 오분류율이 실제보다 낮게 나오고, 그게 이 프로젝트의 결론이 된다. 그리고 **오염이 결과가 좋아지는 방향이라 알아채기 어렵다.**

그래서 측정 1·8ⓐ-1 의 숫자를 읽을 때는 **이 파일을 같이 봐야 한다.**

### 경계 9건을 AI 가 쓴 경위

D-046 ⓑ 와 `PRD.md` §8 (3) 은 **경계에 걸리는 문의를 사람이 직접 쓰도록** 정하고 있다. 결론(측정 8ⓐ-1)이 갈리는 자리이기 때문이다.

그런데 0단계가 `Day 1 오전` 마감인데 본문이 비어 있어 파이프라인을 못 돌리는 상태였고, **일단 채워서 진행하고 사람이 나중에 교체하는 쪽**을 팀이 택했다. 규칙을 몰라서가 아니라 알고 넘긴 것이므로 여기 남긴다.

**그래서 지금 상태로 잰 측정 1·8ⓐ-1 은 최종값이 아니다.**

### AI 가 쓴 경계 문장이 왜 문제인가 — 구체적으로

Claude 는 §7 의 *"원인이 아니라 고객이 요구하는 조치로 분류한다"* 규칙을 이미 알고 있다. 그래서 함정을 **일부러** 심어도, 정답으로 가는 단서를 자기가 읽기 좋은 형태로 남긴다.

| id | 정답 | 심어둔 함정 | 남아 있는 걱정 |
| --- | --- | --- | --- |
| 1 | `DELIVERY` | 불만 톤을 앞에 깔아 `COMPLAINT` 로 유도 | 요구("어디쯤 있는지 알려주세요")가 문장 끝에 또렷하게 남아 있다 |
| 6 | `RETURN_REFUND` | 고객이 "취소"라고 말해 `ORDER_CHANGE` 로 유도 | "어제 받았는데"가 앞에 있어 발송 후임이 명확하다 |
| 11 | `PAYMENT` | "취소한 주문 금액이랑 비슷한데"로 `RETURN_REFUND` 유도 | |
| 16 | `PRODUCT` | "전에 산 게 고장나서"로 `RETURN_REFUND` 유도 | |
| 21 | `ACCOUNT` | "카드 등록하려고"로 `PAYMENT` 유도 | |
| 26 | `ORDER_CHANGE` | 고객이 "환불"이라고 말해 `RETURN_REFUND` 유도 | "상품 준비중"이 발송 전임을 명시한다 |
| 31 | `PROMOTION` | "결제하려고 보니까"로 `PAYMENT` 유도 | |
| 36 | `SERVICE_USAGE` | "청소기 필터 교체 주기"로 `PRODUCT` 유도 | |
| 41 | `COMPLAINT` | 배송·환불 단어를 다 넣되 **요구를 안 씀** | "뭐 바라는 건 없고"가 너무 친절한 단서다 |

**실제 고객은 이렇게 안 쓴다.** 요구를 문장 끝에 정리해주지 않고, 발송 전인지 후인지도 안 밝히고, "바라는 건 없다"고 말해주지도 않는다. 사람이 다시 쓸 때 **위 「남아 있는 걱정」 칸부터 지우는 것**이 핵심이다.

- 위 표가 **다 채워지기 전에 잰 측정 1·8ⓐ-1 은 예비값**이다. 최종 결과로 쓰지 않는다

- 차이가 크면 **D-046 ⓑ 규칙이 옳았다는 증거**가 되므로 `RETROSPECTIVE.md` 에도 옮긴다
